GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。自分のマシンでリアルタイムに作業するため、VS Code の Copilot Chat にはツール呼び出しやファイル編集が逐次表示されます。各差分を確認し、変更ごとに採用または却下できます。エディターを離れずに追加のプロンプトで会話を誘導し、作業を改善したり拡張したりできます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- ハイ コントラスト モードとともにライト モードの切り替えを追加するよう、エージェントに指示します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加します。新しい会話を最初から始めるのではなく、既存のセッションに追加の指示を出して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
    - **Keep** を選択すると変更を採用します。
    - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したすべてのファイルを確認することもできます。

> [!NOTE]
> ツール呼び出しの許可を求められた場合 (たとえばターミナル コマンドの実行)、エージェントは一時停止して **Allow** を表示します。許可するのは、内容を確認して問題ないと判断したコマンドだけにしてください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライト モードの追加を依頼する

ハイ コントラスト モードを実装できたので、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けるため、エージェントはこれまでの作業、変更したコンポーネント、スタイルの方法、設定した local storage のパターンを保持しています。

1. Copilot Chat の入力欄に次のフォローアップ プロンプトを送信します。

    ```plaintext
    よくできました。次にハイ コントラストの切り替えと並べて、ライト モードの切り替えを追加してください。ライト モードも同じパターンに従い、local storage で設定を保持して、UI の同じ場所から利用できるようにしてください。ハイ コントラストとライト モードは、それぞれ独立して有効にできる必要があります。
    ```

2. エージェントは既存の変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラストのときと同様に、各編集を確認します。差分ごとに **Keep** または **Undo** を使います。
4. エージェントの進め方が希望と異なる場合 (たとえば切り替え UI のリファクタリングが好みではない場合) は、チャット入力欄の横にある **Stop** ボタンで停止して、追加の説明を送信します。

> [!TIP]
> 実行中のセッションに指示を追加すると、最初からやり直すよりも速く進められます。フォローアップ プロンプトを使って調整を依頼します (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方針を修正します (「3 つ目の切り替えは追加せず、既存の設定パネルにライト モードを統合する」)、範囲を拡張します (「両方の切り替えにキーボード ショートカットも追加する」)。

## 変更内容を確認する

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更したファイルをいくつか開き、差分を確認します。カスタム エージェントが指定したアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージングしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat agent mode を使って、進行中のセッションを監視し、指示を追加しました。ファイル編集を確認して採用または却下し、コンテキストを保ったままフォローアップ プロンプトで作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または却下する。
- フォローアップ プロンプトを使って実行中のセッションに指示を追加する。

[次のレッスン][next-lesson]では、アクセシビリティ関連の作業をプル リクエストとして公開し、このラボでローカル カスタム エージェントが行った変更を確認します。
