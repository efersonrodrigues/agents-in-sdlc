`quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザーから絞り込み機能を確認しました。次は、明確に定義した QA プロセスを持つカスタム エージェントにこれらの機能をまとめます。

このレッスンでは、次の操作を行います。

- カスタム エージェントが指示、スキル、MCP ツールを使う方法を確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、絞り込み issue に照らして結果を確認します。

## シナリオ

Tailspin Toys は、プル リクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト カバレッジ、ブラウザー上の動作を一貫して確認したいと考えています。カスタム エージェントを使うと、この QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタム エージェントとは

カスタム エージェントは、Markdown プロファイルで定義する、Copilot の特化バージョンです。プロファイルでは、エージェントの目的、指示、利用できるツールを説明します。このワークショップでは `.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明します。`quality-checks` スキルは繰り返し可能なチェックをまとめます。Playwright MCP はブラウザー ツールを提供します。QA プロファイルは、要件を評価して結果を報告するためにこれらの機能をどう使うかを Copilot に指示します。既存の機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を作成する前に、再利用可能な QA プロファイルを Copilot に作成させます。プロファイルでは、QA が実行するチェックと、その作業の範囲の両方を定義します。

1. Codespace に戻り、絞り込みの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のようにカスタム エージェントの作成を依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタム エージェントを作成してください。機能が issue と合意済みの要件を満たすか確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP を使って動作を検証してください。テスト カバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を示して pass、fail、blocked のいずれかを報告してください。実装コードを変更する前に質問し、変更をコミットしたりプル リクエストを作成したりしてはいけません。

   今はプロファイルの作成だけを行い、私がレビューできるようにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA ワークフローと作業範囲がプロファイルに反映されていることを確認します。これにより、検証だけを行いたいときに、範囲が不明確なエージェントが機能を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は省略できますが、含めると分かりやすい表示名になります。
3. プロファイルの指示を読み、QA が要件を基準とし、リポジトリの指示に従い、`quality-checks` スキルを実行し、Playwright MCP を使うことを確認します。
4. QA が根拠を報告し、実装コードを変更する前に質問し、変更をコミットしたりプル リクエストを作成したりしないことを確認します。
5. 必要な責任や境界がプロファイルに反映されていない場合は、続行する前に既定のエージェントに修正を依頼します。

## issue を基準に QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じ絞り込みの会話を再開し、QA を選択します。これで既にコンテキストに含まれる issue と計画を利用できます。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェントの一覧に表示されない場合があります。以下のコマンドを実行すると有効になります。

2. 次のプロンプトで機能のレビューを依頼します。

   ```plaintext
   issue と計画で決めた内容に照らして、絞り込み機能をレビューしてください。PR を作成できる状態ですか。
   ```

3. QA エージェントが作業を始めます。
4. 完了したら、エージェントのレポートを確認します。
