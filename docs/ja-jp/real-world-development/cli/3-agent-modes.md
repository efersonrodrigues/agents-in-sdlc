最初にプロジェクトへ小さな機能を追加しました。より大きな変更には、さらに堅牢なプロセスが必要です。GitHub Copilot CLI は組織の既存の開発フローに沿って動作し、適切なものを適切な方法で構築できるよう支援します。このレッスンから、典型的なエージェント主導の開発プロセスに沿って進めます。まず issue を使って新機能を作成し、コードが正しく、機能が想定どおりに動作することを確かめてから、プロジェクトにマージします。

> [!NOTE]
> 機能の作業を続ける間、同じ会話とブランチを使います。通常は異なるファイル形式ごとに別のブランチや PR を使いますが、ここでは主な概念に集中するため手順を簡略化します。

このレッスンでは、次の操作を行います。

- GitHub issue から Copilot の会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動で検証します。

機能の作業を続ける中で、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して、QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のゲーム カタログが増え、訪問者がカテゴリとパブリッシャーでゲームを絞り込める必要があります。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、実装前に合意しておく詳細があります。Plan モードで決定事項を整理し、Autopilot に範囲を定めた実装を依頼します。

## 背景

AI コーディング エージェントを開発フローに導入しても、基本は変わりません。むしろ、さらに重要になります。多くの開発者は次のような流れで作業します。

1. 作業内容を記述した issue から始めます。
2. 実装計画を作成します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プル リクエスト (PR) を作成します。
7. コード レビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細はチームや組織によって異なりますが、多くの場合は上記の流れを基にしています。

この標準的な方法に従うと、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビュー プロセスを通るようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前にユーザーの入力を待ちます。
- **Plan**: エージェントは最初に計画を作成し、プロジェクト ファイルを編集できません。
- **Autopilot**: エージェントはコードを書き、テストを実行し、タスクが完了するまで反復して自律的に作業します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue から開始する

絞り込み機能の作業を始める前に、Codespace に戻ってリポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動してから続行します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、絞り込み機能のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーを使って **Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まることを確認します。`#` を使うと、GitHub 上の issue やプル リクエスト (PR) をコンテキストに追加できます。

## 絞り込み機能を計画する

計画を立てると、Copilot に作業を依頼する前に機能の実装方法を定義できます。複雑な作業では、少し時間を取って計画することをお勧めします。Plan モードに切り替え、Copilot に計画を作成させましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した issue の参照の後に、次のプロンプトを入力します。

   ```plaintext
   この機能を実装するための計画を作成してください。
   ```

Copilot はプロジェクトを調べ、最適な方法を検討して計画を作成します。

3. 絞り込み機能の動作について質問された場合は、希望に基づいて回答します。ここでは正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して展開します。
5. 計画を上下にスクロールして確認します。
6. 決定した内容と合わない部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成して確認できたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot では、Copilot がタスクを完了したと判断するまで、問題への対応を反復します。

1. **Accept plan and build on autopilot (recommended)**、またはインストールしたバージョンにある同様のオプションを選択します。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が計画に沿って作業を進め、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まることがあります。必ず先に計画を確認してください。依存関係が不足している、またはポートが競合していると Copilot が報告した場合は、チェック完了と判断する前にセットアップの問題を解決します。

## 実装をレビューして検証する

コードが生成された後は、他のコードと同様にマージ前にレビューします。コードを確認し、サイトを実行して問題がないか確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、絞り込みの実装とテストを確認します。
3. issue と計画中に決めた内容に照らして結果を確認します。
4. コードのレビューが終わったら、<kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新しい機能を試す

コードは問題なさそうですが、実際に動作するでしょうか。前と同じようにアプリを起動し、Codespaces が転送するポートからサイトを開きます。

1. Copilot に次のようにアプリの起動を依頼します。

   ```plaintext
   ブラウザーで絞り込み機能を試せるように、アプリを起動してください。URL を教えて、サーバーは実行したままにしてください。
   ```

2. Codespaces からポート `4321` が利用可能であると通知されたら、**Open in Browser** を選択します。
3. 計画で決めたカテゴリとパブリッシャーの絞り込み、および組み合わせを試します。
4. リセットと結果がない場合の動作が、issue と決定事項に合っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーを停止するよう依頼します。

## まとめと次のステップ

異なる会話モードを使って機能を作成し、レビューしました。このレッスンでは、次の作業を行いました。

- GitHub issue から Copilot の会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新しい機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動検証しました。
